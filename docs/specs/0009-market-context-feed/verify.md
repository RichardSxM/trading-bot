The recorder logs from that time were lost when the 18:40 deploy recreated the container. It happened while the old per message writer was overloaded (spec 0012). Since the 4d55abd deploy (18:40 UTC) the longest open interest gap is 3.8 s. Liquidation hours: 2026-10-15 13:00 (4 rows, 13:11:54 to 13:30:59), the first liquidations recorded. Owed to `/debug`.

   **/debug (2026-10-16): cause proven, a spec gap, owed to `/architect`.** The run's own files were still on the VPS. (1) The feed was starved, not stalled at Kraken. Nautilus's `_run_data_queue` loops on `await self._data_queue.get()`, which returns without yielding while the queue holds items, and Kraken's Rust thread kept the queue full while the old writer lagged. So no other task on the loop ran: the idle timer could not fire, and a reconnect could not open within `OPEN_TIMEOUT_S`. The open interest rows show it: `ts_init − ts_event` grew from 0.2 s to 22 s and then 105 s at 12:20 to 12:30, before an `idle` outage from 12:32:25 to 13:04:29 that was logged; it reached 23 s at 13:30 and 38 s at 13:55, with no rows at all from 13:35 to 13:55, before the silence from 13:58:56; it reached 31 s at 15:35 to 15:40, before an `idle` outage at 15:42 in the next run. A plain asyncio repro (a thread keeps a queue fuller than the consumer can drain) gave zero firings of a 1 s `wait_for` in 6 s. Spec 0012 removed the backlog, but the feed still shares the loop with a queue that can starve it. (2) The missing gap row follows the spec as written: AC-6 writes an outage line only when the feed comes back (`end_ns` is the first message after), and AC-7 `silence` only spans two rows of one run, so an outage still open when the run ends leaves no trace. The code matches both rules; they need an amendment (for example an open outage line written at `context_feed_down` and closed by the compactor at the run's end), not a patch.
