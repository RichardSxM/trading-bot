# 0004. Verify: design system and dashboard shell

Manual checks for `/check verify`, run on the laptop with `TRADING_ENV=demo` after `docker compose build && docker compose up -d`. Each names the criteria it proves.

1. **Credentials.** Run `scripts/dev-secrets.sh` on a fresh `./secrets`: it creates `dashboard_session_key` and prints the "next" line. Run `docker compose build dashboard && scripts/dashboard-credentials.sh --dev --write`: it works with the two files still missing, prints a dev password and an `otpauth://` QR, and writes both files. Add the QR to an authenticator app. Rerun both: every file kept. Run `ps` while the script waits for input: no secret in any argument list. On the VPS, write the files with `sudo scripts/dashboard-credentials.sh --write` (the folder belongs to root), then `chown 10001 … && chmod 0400 …` as for spec 0003. Proves **AC-19**.
2. **Refusals.** Move `dashboard_totp_seed` away and start the dashboard: exit 1, `secret_unavailable`. Put back a hash that is not argon2id: invalid configuration, exit 1. Set `TRADING_ENV=live` with `DASHBOARD_COOKIE_SECURE=false`: refused. Proves **AC-5**.
3. **Login.** Open `/` without a cookie: redirected to `/login?next=/`. Log in with password and code: back on `/`; the browser shows `kfs_session` as HttpOnly, Secure, SameSite Strict. If your browser drops the cookie on http and sends you back to login (Safari can), set `DASHBOARD_COOKIE_SECURE=false` in `.env`, demo only. Try `next=//evil.example`: lands on `/`. Reuse the same code in a second login: refused, log shows `replayed_code`. Proves **AC-1**, **AC-3**.
4. **Lockout.** In a private window, fail 5 times, then enter the right password and code: `429`. The first window still works. Logs show 6 `login_failed` lines with no submitted value. Proves **AC-2**.
5. **Session.** Edit one character of the cookie: back to login. Replace `dashboard_session_key`, restart: every window back to login. Log out: cookie gone. With `DASHBOARD_SESSION_IDLE_H` set low for the test, the "session ends" cue appears in the top bar; let it expire with the page open, tap stop: login page says the stop was NOT sent, and after login you land back on the page you were on. Proves **AC-1**, **AC-4**.
6. **Shell on desktop and phone.** At 1280 wide: side nav, top bar with `DEMO` badge, title `DEMO · …`, demo favicon. At 360 × 640 (browser device mode and a real phone over Tailscale): bottom tabs, stop button fully visible and at least 44 px. Each of the four pages shows its empty state. Proves **AC-6**, **AC-7**.
7. **LIVE treatment.** Start only the dashboard with `TRADING_ENV=live` and live secrets placeholders (no trader): red `LIVE` badge, red top border, `LIVE ·` title, live favicon. Proves **AC-7**.
8. **Data age.** With the trader running: age neutral, ticking. `docker compose stop trader`: amber after 3 s, red within 11 s, `no heartbeat` after about 30 s. Start it again: neutral. Stop Redis while the trader runs: the trader keeps running, one `snapshot_write_failed` per minute. Proves **AC-8**, **AC-9**.
9. **Link status.** `docker compose restart dashboard` with a tab open: link `reconnecting` then `live`, values dimmed and labelled `link lost` meanwhile. `docker compose pause dashboard` for 20 s: `reconnecting` after about 5 s, `lost` after about 15 s. Proves **AC-10**.
10. **Stop.** Tap stop: `docker compose exec redis redis-cli --user trader --pass … XRANGE demo:control - +` shows one new entry with the five fields, `expires_at` 300 s after `issued_at`. State reads `stop sent · awaiting trader`. Open the page on the phone: same state. Append `XADD demo:control:results * id <id> outcome executed outcome_at <now> schema_version 1` as `trader`: `confirmed` within 1 s. Tap again and wait past expiry with no result: `not handled, expired`. Proves **AC-11**, **AC-12**.
11. **Stop without JavaScript.** Disable JavaScript, tap stop: the full page reloads with the new state and a new stream entry. Send the POST with curl without the CSRF field: `403`, no entry. Proves **AC-11**.
12. **Stop with Redis down or hung.** `docker compose stop redis`, tap stop: red `Stop NOT sent` with retry, ERROR `control_send_failed`, never `sent`. Repeat with `docker compose pause redis`: the same within about 1 s. On the phone, load the page, switch on airplane mode, and tap stop: `Stop NOT sent` in the browser. Proves **AC-13**.
13. **ACL.** `docker compose run --rm -T dashboard pytest -q -m redis`: the dashboard user reads both streams and still gets `NOPERM` for `SET`, `DEL`, `FLUSHDB`. Proves **AC-14**.
14. **Design system.** Unit test for token parity and contrast passes inside the image (it reads `/app/DESIGN.md`); open `/styleguide`: every component in every state from `DESIGN.md`, and the chart sample draws with no CSP error in the console. Run `impeccable critique` on `/styleguide` and the shell; no open high severity finding. Proves **AC-15**, **AC-16**, **AC-17**.
15. **Headers and origins.** DevTools network tab on every page: every request goes to the dashboard's own origin; response headers include the CSP, `nosniff`, `Referrer-Policy: same-origin`, `no-store`; the console shows no CSP violation. Proves **AC-18**.
16. **Stop path edges** (added by `/develop`, stop path milestone). Tap stop three times quickly: three entries with three different `id`s (no debounce). Log in again in a second tab, then tap stop in the first (stale token): `403` and "Stop NOT sent: reload the page", no entry; tap the retry button: sent. After a `confirmed` result, wait 15 minutes: the command state reads `none`. Append a result with `outcome exploded` for the latest `id`: amber `unknown result` and one WARNING `control_result_invalid`, not one per poll. With JavaScript off and Redis stopped, tap stop: the full page with `Stop NOT sent`, status `503`. Proves **AC-11**, **AC-12**, **AC-13**.
17. **Stop value sources.** Compare the new entry's `issued_at` to `date -u` on the host: within a second (dashboard UTC clock). Set `CONTROL_COMMAND_TTL_S=60`, restart, tap stop: `expires_at` is 60 s after `issued_at`. Run the same tap with `TRADING_ENV=live` on a dashboard alone: the entry lands in `live:control`, never `demo:control`. Proves **AC-11**, **AC-12**.
