# Review, main, 2026-10-01

**Reviewed by**: Sonnet 5.5 (author on a different model)
**Scope**: 56 files, uncommitted (whole scaffold on main)
**Verdict**: Changes requested

## Summary
This is a clean first slice: a uv workspace, three Compose services plus postgres, redis, migrate and a backup stub, a shared boot sequence (settings, JSON logs, env guard, clock check), and a guard that stops demo from ever building a Kraken execution client. The code follows the spec closely and the tests are meaningful. The headline issue is that every service loads the whole `.env`, so the "dashboard never receives Kraken keys" rule is not enforced by anything once feature 4 puts keys there. The rest is minor hardening.

## Major
### 🟠 Every service gets the whole `.env`, `compose.yaml:13`
**Problem**: The shared `x-app` block sets `env_file: .env` for migrate, trader, recorder and dashboard. Whatever lands in `.env` (today Postgres settings, later Kraken keys and secrets from feature 4) is injected into all of them. Only trader and recorder run the env guard. The dashboard (the only service reachable from a network) and migrate have no check at all.
**Why it matters**: The spec says the dashboard and backup never receive Kraken keys. On the VPS, live keys in `.env` would also make the recorder refuse to start (the guard fires for the recorder in every environment), so feature 4 will hit this immediately. Today it is latent, but it is real money and the fix is cheap now and awkward later.
**Suggested fix**: Drop the shared `env_file` and give each service only what it needs, either with `environment:` lists using `${VAR}` substitution or per service env files. Keep Kraken keys out of any file the dashboard and recorder read. Also run the Kraken key check in the dashboard boot as a refuse to start rule.

## Minor
### 🟡 SNTP reply is not validated, `packages/core/src/trading_core/clock.py:48`
**Problem**: The reply is trusted as is. It does not check the mode, stratum, leap indicator, that the originate timestamp matches what you sent, or that the reply came from the server you asked.
**Why it matters**: A "kiss of death" or rate limit reply (stratum 0, zero timestamps) gives an offset of decades. If most servers answer that way the trader and recorder refuse to start for a clock problem that does not exist, and Docker's restart loop hits the pool harder, making it worse. Spoofed replies could also pass or fail the check.
**Suggested fix**: Reject replies that are not mode 4, have stratum 0 or leap indicator 3, or whose originate timestamp does not equal the one sent, and treat them as "did not answer". Compare the reply address to the server address. Add tests for these cases.

### 🟡 Invalid `LOG_LEVEL` crashes with a raw traceback, `packages/core/src/trading_core/settings.py:17`
**Problem**: `log_level` is any string uppercased. `configure_logging` then calls `root.setLevel("VERBOSE")`, which raises ValueError after settings "validated".
**Why it matters**: A typo gives a non JSON traceback instead of the one clean `invalid configuration` line the spec promises. Nautilus also takes its own level names.
**Suggested fix**: Make `log_level` a Literal of the supported names so pydantic rejects it in the normal path.

### 🟡 Database URL does not escape the password, `packages/core/src/trading_core/settings.py:46`
**Problem**: The URL is built with an f string. A password with `@`, `/`, `:` or `%` breaks it or points at the wrong host.
**Why it matters**: It will bite when feature 4 introduces real generated passwords, and the failure will look like a connection error.
**Suggested fix**: Build it with `sqlalchemy.URL.create(...)`.

### 🟡 The guard checks one config object, the node uses another, `apps/trader/src/trader/main.py:48`
**Problem**: `guard` calls `build_config()` and `main` calls `build_config()` again for the real node (same in the recorder). The spec says the guard checks "the final `TradingNodeConfig`, before `build()`". Today both are identical, but nothing ties them together, and `boot(guard=None)` silently skips the guard.
**Why it matters**: Once configs gain conditions (feature 6 sandbox, feature 4 live), a difference between the two builds would let a config pass the check that is not the one that runs. This is the safety rail for "demo never trades for real".
**Suggested fix**: Build the config once, check that object, and pass the same object to `TradingNode`. Consider making `guard` required for node kinds.

### 🟡 Heartbeat only proves the event loop is alive, `packages/core/src/trading_core/node/heartbeat.py:25`
**Problem**: The recorder is "healthy" even if the Kraken websocket is dead and nothing is being written.
**Why it matters**: A silent recording gap looks healthy. Spec assigns gap detection to feature 8, so this is only a heads up, but the health check name suggests more than it checks.
**Suggested fix**: Note it in feature 8's scope, or have the recorder touch the file only when data arrived recently.

### 🟡 A lowercase explicit node id makes a separate Redis key space, `packages/core/src/trading_core/naming.py:35`
**Problem**: `TRADER-demo` is accepted (the spec allows case insensitive tags), but Nautilus keys become `trader-TRADER-demo:...`, which is a different namespace than `TRADER-DEMO`. The test locks this in.
**Why it matters**: A restart with a different casing would not reload positions. Flush by pattern would also miss it.
**Suggested fix**: Return a normalized id (name upper, tag upper) instead of the raw explicit string, or refuse non canonical casing.

### 🟡 Dashboard listens on 0.0.0.0 by default, `apps/dashboard/src/dashboard/main.py:26`
**Problem**: The spec says no service binds `0.0.0.0`. It is done on purpose inside the container with a loopback only publish in Compose, but if anyone runs it with host networking or a different publish line it is open to the network.
**Why it matters**: This is the page that will hold the kill switch.
**Suggested fix**: Keep it, but add a comment in `compose.yaml` and a verify step that fails if the port is published on anything but 127.0.0.1 (verify.md already checks `docker compose port`).

### 🟡 No init process and floating image tags, `compose.yaml:27,46,159`
**Problem**: The backup stub runs `sleep infinity` as PID 1, which ignores SIGTERM, so stops take the full grace period. `postgres:16-bookworm`, `redis:7-bookworm` and `alpine:3.20` are tags, not digests, while NautilusTrader is pinned exactly.
**Why it matters**: Slow stops are cosmetic. A silently moved Postgres or Redis minor release on a live box is a small but real risk.
**Suggested fix**: Add `init: true` to the stub. Pin tags to a minor or digest, or leave this for feature 7 (deploy mechanics) and note it there.

### 🟡 `.dockerignore` does not mirror secret patterns from `.gitignore`, `.dockerignore:1`
**Problem**: `secrets/`, `*.key` and `*.pem` are ignored by git but not by Docker. `COPY apps` and `COPY packages` would bake any such file placed under them into an image layer.
**Why it matters**: Low chance today, but images may be pushed later and this is a real money project.
**Suggested fix**: Add the same patterns to `.dockerignore`.

### 🟡 Heartbeat and migration run paths are not tested, `packages/core/tests/test_node.py:36`
**Problem**: Tests only check heartbeat config values. Nothing runs `_beat`, `on_start` creating the folder, or alembic upgrade against a database (only the revision graph is checked).
**Why it matters**: Both are health and startup critical. They were proven by the runtime verify, but not locked by a test.
**Suggested fix**: Add a test that calls `_beat` on a temp path, and later an upgrade test with a throwaway Postgres once feature 3 adds tables.

## Nits
- ⚪ `packages/core/src/trading_core/logs.py:32`, `entry.update(extra)` lets a caller overwrite `level`, `msg` or `ts`. Skip reserved keys.
- ⚪ `apps/trader/src/trader/main.py:62`, the heartbeat wiring line is duplicated in the recorder. A small shared helper in `trading_core.node` would keep them aligned.
- ⚪ `packages/core/src/trading_core/clock.py:101`, dashboard logs "clock check passed" at WARNING. It matches the spec text, but it will look odd in dashboards of logs.
- ⚪ `apps/dashboard/tests/test_smoke.py:14`, the "does not import nautilus" test passes trivially if the dashboard image simply does not have it. Fine as a tripwire, but it is not a strong check.

## Strengths
- The env guard is a real allowlist with a clear refusal path (`env_guard_refused`, exit 1), runs before the clock check, never prints key values, and has tests for the trader (demo and live), the recorder (both envs) and boot ordering.
- Redis and node id separation between demo and live is handled with one helper and tested, including mismatched explicit ids.
- Settings errors are logged with `include_input=False`, with a test that a bad value is never echoed.
- Compose is tidy: loopback only port, health checks, memory limits, OOM priority for the trader, log rotation, no published postgres or redis.
- Docker build caches dependency layers and runs as a non root user.

## Test coverage
Good for a scaffold: 127 tests cover boot order and refusals, the env guard, naming, clock policy (with injected query), settings, logs, health file freshness, redis check, and each app's config. Gaps are the SNTP reply validation (no tests because no validation), the heartbeat actor behavior, an actual migration run, and that `main()` for the recorder is not exercised with a fake node the way the trader's is.
